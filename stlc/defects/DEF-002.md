# DEF-002: POST /messages returns the stored message, not AddContactMessageResponse `{ success }`

## Summary

A valid `POST /messages` returns 200 with the stored message (`id`, `status: "NEW"`,
`created_at`, the sent fields, plus `user_id` when authenticated) and no `success` field. The
contract documents the 200 body as `AddContactMessageResponse` `{ success: boolean }`. The contract
does not mark `success` as required, so `toMatchContract` passes, but the documented field is never
returned. The same failure hits
`tests/api/contact-form/TC-009-anonymous-send-ui-body.spec.ts:13` (anonymous) and
`tests/api/contact-form/TC-026-authenticated-send.spec.ts:14` (authenticated).

## Steps to reproduce

1. `POST https://api.practicesoftwaretesting.com/messages` with
   `{"name":"QA Tester","subject":"webmaster","message":"This is an automated test message from a QA test run. Please ignore it.","email":"qa.tester@example.com"}`.
2. Read the JSON response body.

## Expected

AC-11: returns 200 "with a JSON body matching the contract's `AddContactMessageResponse` schema
(`success: boolean`)". 02 also states `success: true`.

## Actual

200 with
`{"name":"QA Tester","email":"qa.tester@example.com","subject":"webmaster","message":"…","status":"NEW","id":"01m59avmqcpr6bqjv7mh8591qe","created_at":"2026-10-19 05:41:25"}`.
`success` is absent (`typeof body.success` is `"undefined"`). Same on retry, both signed out and
signed in. Either the API or the contract is wrong: the response matches the `ContactResponse`
schema, so the contract probably needs to change to that.
