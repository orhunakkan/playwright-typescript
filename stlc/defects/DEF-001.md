# DEF-001: Message minimum-length alert is not shown on blur before the first Send

## Summary

On a fresh `/contact` form, a 49-character Message that loses focus shows no "Message must be
minimal 50 characters" alert, although the field is invalid, dirty and touched. The alert appears
only after "Send" has been clicked once. Also hit by
`tests/a11y/contact-form/TC-019-min-length-alert.spec.ts:13`, which needs the same state.

## Steps to reproduce

1. Signed out, open `/contact`.
2. Fill Message with "Automated QA test message. Please ignore this one" (49 characters).
3. Move focus out of the field (Tab).

## Expected

AC-6: "when the Message has 49 characters and the field loses focus (or "Send" is clicked), then
the alert "Message must be minimal 50 characters" is shown."

## Actual

No `message-error` element is rendered, even after 5 s. In the trace's DOM snapshot after Tab, the
textarea's classes are `form-control ng-invalid ng-touched ng-dirty`, so Angular has marked the
control invalid and touched; the template simply does not show the error until the form has been
submitted. Clicking "Send" with the same text does show the alert (TC-018 passes). The result was
the same on retry and in both the chromium and a11y projects.

Note: AC-6 was inferred (01 `source: inferred`), and 01's "Validation timing" question already
saw errors only after Send. The planner's "49 + blur shows the alert" (`ui-scenarios.md`,
observation 5) came after a Send in the same session. If the product owner confirms that
validation runs only after submit, close this as wont-fix and amend AC-6.
